# Nova: project rules (read first)

Source of truth: `docs/DECISIONS.md`, then `docs/HANDOVER.md`. If any other file in the repo disagrees with them, they win.

## What Nova is
A Duolingo-style, level-based study app for primary students in India (grades 1–4 built first, designed for 1–7). Marathi and English. A placement test assigns the starting level. Levels are story scenes with questions, generated by an LLM from a fixed asset catalogue.

## Always
- Treat the app as **online-hybrid**: it assumes internet but must keep working on weak connections (cached levels, an offline fallback level, queued sync).
- Keep the existing stack unless told otherwise: Flutter, Riverpod, Drift/SQLite, `flutter_tts`, `speech_to_text`.
- Support both Marathi and English everywhere. Check that any font used has Devanagari glyphs.
- Keep tasks small: one branch per task, one concern per commit.
- Run `flutter analyze` and `flutter test` before saying a task is done, and say plainly what you could not run.
- Ask a human when an open question in `docs/DECISIONS.md` blocks you. Do not guess.

## Never
- Never put API keys in the app source or in git.
- Never add new client-side LLM calls. Existing ones in `llm_game_master_service.dart` are a temporary stopgap and are being moved to a backend.
- Never reintroduce class-based levels (Std 1, Std 3, Std 4 and similar). Levels come from the placement test and the skills graph.
- Never create another app shell or another `main()`. There is one app.
- Never delete or stub out the Bluetooth duel. It is required.
- Never change the level JSON contract without explicit human approval.
- Never add a new level by hard-coding it: no new `levelNum == n` branches, no new per-level stage or painter widgets, no hand-written per-level story text in Dart. Levels 1–4 were built that way and are legacy. New content goes through the contract, the catalogue and the pipeline.
- Never add features outside the current phase in `docs/HANDOVER.md`.
- Never delete branches or force-push without asking.
